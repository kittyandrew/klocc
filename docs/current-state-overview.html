Hierarchy Options, Visually

Hierarchy means how the DAG data is projected into nested treemap rectangles. The same source units can be grouped different ways without changing the underlying DB.

Source kind -> unit

Top-level rectangles are categories like Cargo crates, fixed-output sources, patches, generated outputs. Inside each are individual source units.

cargo-vendored-crate
  rocket
  tokei
fixed-output-source
  gcc.tar.xz
  bash.tar.gz
patch-source
  bash53-001

Runtime package -> source

Top-level rectangles are runtime outputs like klocc or glibc. Inside are the sources attributed to that output and its build graph.

klocc
  workspace source
  cargo vendor deps
  glibc source
  bootstrap inputs

Derivation tree -> source

Top-level shape follows Nix build derivations. This is most provenance-accurate, but can be visually noisy for bootstrap graphs.

klocc.drv
  cargo artifacts drv
  stdenv-linux.drv
    bash.drv
    gcc.drv

Ecosystem -> package

Top-level rectangles group by ecosystem: cargo, nix, cargo-workspace. Useful for broad composition, less precise for provenance.

cargo
  rocket
  prometheus
nix
  glibc
  gcc
cargo-workspace
  klocc

Recommended first default: source kind -> unit, because it is simple, fast to explain, and makes generated/fixed-output/patch categories visible.

Tree Views

nix shell nixpkgs#sqlite -c sqlite3 /tmp/klocc-self.sqlite '

from scan_health

from source_rollup
group by runtime_linked, build_time_only;
'

Design Decisions Locked In

There is one complete scan path. No runtime-only shortcut mode. Runtime, build-time, unique, and shared views are filters over the complete SQLite artifact.
DecisionCurrent Choice
Machine formatSQLite only. Extra JSON output is out of scope.
LOC enginetokei with policy hash tokei-v14-source-graph-v2.
Cache identityNix store path plus counter policy first.
Source realizationAutomatic for discovered source store paths.
Derivation graphPersisted as first-class normalized tables.
UnknownsRecorded honestly and linked back to derivations.

Known Limitations

  • No unknown derivation sources remain in the self-scan. The previous unknown bucket is now split into concrete source/fetch classifications and generated bootstrap intermediates.
  • 271 generated derivation outputs remain. These are not direct source units; they are bootstrap intermediates generated from input derivations.
  • Unique/shared source rollups are graph based. They are useful for hiding reused dependencies, but they are not yet a formal Nix ownership algorithm for source LOC.
  • Persistent LOC cache is local. It lives under ~/.cache/nix-system-treemap and is keyed by store path and policy, not content hash yet.
  • Source inference is heuristic. It now handles patches and common source/script extensions, but more Nixpkgs conventions need to be learned.
  • Native UI is still deferred. The artifact is being shaped so a later GPUI app can consume it directly.

Next Useful Work
